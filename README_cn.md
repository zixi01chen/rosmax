# rosmax — ROS2 通信压测与实时监控平台

[English](README.md) | 中文


**部署在 x86 电脑上，连接 aarch64 板子（如 RDK S600），一条命令拉起组内全互联压测拓扑，浏览器实时查看每条链路的时延、频率、丢包。**

English: [README_EN.md](README_EN.md)

## 它解决什么问题

机器人系统里"节点间通信到底撑不撑得住"靠猜不行。rosmax 在目标板上生成 **G 组 × 每组 N 个节点**的全互联压测拓扑（组内每对节点间一条独立话题，方向含于话题名如 `n0_n1`），然后给你一个浏览器面板，实时回答：

- 每条链路的时延分布（mean / p50 / p99 / max）
- 每条话题的实际接收频率 vs 配置频率
- 丢包数与丢包率（含过载降速时的诚实呈现）
- 全网总吞吐、板温、板负载

## 架构

```
┌─────────── x86 电脑 ───────────┐         ┌────── aarch64 板子 ──────┐
│  panel.py  (:8090 Web 面板)     │  SSH    │  mesh_group × G 组        │
│   ├─ 每秒拉取 status.json       │ ◀────── │   ├─ 组内全互联发布/订阅   │
│   ├─ Top10 延迟表 + 时序图      │         │   └─ status_writer.py     │
│   └─ 拓扑控制（应用 G×N）       │ ──────▶ │      └─ 每秒写状态快照    │
│  浏览器 ← http://localhost:8090 │  POST   │  （频率/字节/组数可调）   │
└─────────────────────────────────┘         └───────────────────────────┘
```

- **板端**：`mesh_group` 进程承载一组逻辑节点（独立 ROS 节点名，共享 DDS participant），`std_msgs/msg/String` 标准类型，42 字节定长文本头携带 seq+时间戳
- **电脑端**：面板每秒经 SSH 拉取状态快照；拓扑变更（组数/节点数/频率/字节）通过"应用"按钮下发，秒级生效
- **解耦设计**：面板重启不影响板上压测；板上压测由页面按钮控制

## 快速开始

前置：x86 电脑可 SSH 到板子（`sshpass` + root），板上已有 `/root/rosmax_overlay`（部署包，见 docs/）。

```bash
# 1. 启动面板（默认板上拉起 1 组 × 3 节点 @30Hz）
python3 scripts/panel.py

# 2. 浏览器打开
#    http://localhost:8090

# 3. 在页面上调整拓扑：组数 G / 每组节点数 N / 频率 / 字节 → 点「应用 G×N」
#    例：G=2, N=10, 100Hz —— 2 组 × 10 节点，每组 90 条话题，共 180 条
```

### 板端手动部署（首次或更新后）

```bash
# 将 scripts/ 下的部署脚本推到板端后（overlay 路径 /root/rosmax_overlay）：
ssh root@<板IP> 'bash /root/rosmax_overlay/live_headless.sh start 1 3 30 1024'
```

## 界面说明

| 区域 | 内容 |
|---|---|
| 顶部卡片 | 节点总数 / 话题总数 / 每话题频率 / 总吞吐 / 累计丢包 / **丢包率** / 板温 / 板负载 |
| 压测实时性能 | 每条话题一行（来源→目的地），按延迟降序，**分页浏览全部**；含丢包率列 |
| 时序图 | 延迟最高前 10 条话题的 p50 趋势（60 秒窗口）|
| 设备上的全部话题 | 板上同 domain 全部话题（含外部系统标记），**每页 10 条 + 翻页**，10 分钟刷新一次 |
| 拓扑控制 | 组数 / 节点数 / 频率 / 字节 + 应用与快捷加减按钮 |

数据新鲜度标注：实时（绿）/ 历史数据 · Xs 前（黄，拓扑切换建立期内正常）。

## 指标口径

- **时延** = 接收回调首行时间 − 发布前编码时间（同板 CLOCK_MONOTONIC_RAW，无跨机同步问题）
- **p50 / p99 / max** = 窗口内全部消息时延的分位数——p50 看典型，p99 看最坏 1%
- **丢包率** = loss / (recv + loss)，检测方式为序列号连续性
- **rate** = 该话题的实际接收频率；大拓扑过载时会自动降速（过载保护，诚实降级）

## 容量参考（RDK S600 实测，1KB payload）

| 拓扑 | 话题数 | 频率 | 结果 |
|---|---|---|---|
| 1×3 | 6 | 200Hz | p50 49-91μs，零丢包 ✓ |
| 10×10（100 节点） | 900 | 100Hz | rate 97Hz，零丢包 ✓ |
| 1×50 | 2450 | 10Hz | rate 8Hz，p50 ~88ms ⚠ |
| 100×10（1000 节点） | 9000 | 10Hz | 拓扑全匹配，资源贴顶 ⚠ |

经验规则：μs 级延迟档，每组 `N×(N-1)×频率 ≤ 2 万 msg/s`；全板 ≤ 9 万 msg/s。详见 [docs/w2_acceptance.md](docs/w2_acceptance.md)。

## 目录结构

```
scripts/panel.py            x86 端 Web 面板（:8090）
scripts/live_headless.sh    板端压测生命周期（start/stop，含深度清场）
scripts/topology.sh         板端拓扑管理（ensure G N [RATE] [SIZE]，幂等）
scripts/status_writer.py    板端状态采集器（每秒写 status.json）
rosmax_nodes/src/mesh_group.cpp   板端组容器压测进程
docs/                       设计文档与测试记录
```

## 已知限制

- 单组进程容量 ~2500 msg/s（共享板负载下）；更大规模用多组分摊
- 板重启后运行态不自动恢复——面板点一次「应用 G×N」即可按配置重新拉起
- FastDDS SHM transport 在部分板上有已知问题——系统强制 UDP 单 transport
